# SerenoJS Starter

A minimal [SerenoJS](https://github.com/eutobias/serenojs) starter built on
[Waku](https://waku.gg): React 19 server components, a schema-driven admin
panel, a REST API, cookie authentication and SQLite — with no ORM and no
external services.

The app ships:

- a demo `todos` collection (`src/schemas/todos.ts`);
- a small todos example app that consumes the public API
  (`src/pages/index.tsx`);
- the admin panel mounted at `/admin`;
- content localization configured for `pt` (default) and `en`;
- agent skills that teach coding assistants how to extend the CMS
  (`.agents/skills/`).

## Requirements

- **Node `>=22.15`** (uses `node:sqlite`) or **Bun `>=1.4.3`**
- `pnpm` recommended (`npm`, `yarn` and `bun` also work)

## Getting started

If you scaffolded this project with `create-start-serenojs`, dependencies are
already installed. Otherwise:

```sh
pnpm install
```

Start the development server:

```sh
pnpm dev
```

Then open:

- Example app: <http://localhost:3000>
- Admin panel: <http://localhost:3000/admin>

### First login

The first boot seeds an administrator:

| E-mail | Password |
| --- | --- |
| `admin@example.com` | `admin123` |

Change the password (or create a new user) before deploying. Override the seed
with `ADMIN_EMAIL` / `ADMIN_PASSWORD` **before the first boot**.

## Project structure

```
serenojs.config.ts      # collections, locales and mount paths
.agents/
  skills/
    serenojs-schema/    # agent skill: how to model collections
src/
  schemas/              # SOURCE OF TRUTH for content types
    index.ts            # exports `collections`
    locales.ts          # locale registry + defaultLocale
    todos.ts            # example collection
  middleware/
    serenojs.ts         # mounts @eutobias/serenojs/server
    no-trailing-slash.ts
  pages/
    _layout.tsx         # root layout (imports the stylesheet)
    index.tsx           # todos example app
  styles.css            # example app styles
  pages.gen.ts          # generated by `pnpm typegen` - do not edit
```

There are no admin/API/auth route files: the package middleware answers those
requests before Waku's file-system router sees them.

### Example app

The starter includes a small todos app (`src/pages/index.tsx`) that consumes the
public REST API. It is intentionally self-contained: keep it, rewrite it, or
remove it. You are free to use any component library and any styling solution
you prefer. Nothing in the app is tied to the admin panel, which ships its own
bundled styles and is not affected by the host app.

## Content modeling

Collections live in `src/schemas/` and are aggregated by `src/schemas/index.ts`.
To add a content type:

1. Create `src/schemas/<name>.ts` exporting a `CollectionDef`.
2. Register it in the `collections` array in `src/schemas/index.ts`.
3. Restart the dev server — SQLite is migrated lazily and the admin/API pick up
   the new collection automatically.

Supported field types: `text`, `email`, `textarea`, `number`, `boolean`,
`select`, `date`, `relation`, `media`, `media-list` and `list`.

Collections are private by default for writes. `access` controls each API
operation (`read`, `create`, `update`, `delete`); the demo opens everything up:

```ts
access: { read: "public", create: "public", update: "public", delete: "public" },
```

## AI agent skills

The project ships coding-agent skills in `.agents/skills/`. They are plain
Markdown and are picked up automatically by assistants that support the
`.agents/skills` convention (no build step needed).

- **`serenojs-schema`** — how to create and edit collection descriptors:
  field types, relations, standalone collections, access control, validation,
  localization and naming conventions. It includes a ready-to-edit collection
  template (`assets/collection.template.ts`) and a field reference
  (`references/fields.md`).

When asking an assistant for a new content type, point it at
`.agents/skills/serenojs-schema/SKILL.md` or simply mention that a SerenoJS
collection is needed — the skill documents the project-specific rules so the
schema matches what the admin and API expect.

## Configuration

`serenojs.config.ts` defines the admin mount path, API paths, locales, DB file,
media and backups. Useful environment variables:

| Variable | Default | Purpose |
| --- | --- | --- |
| `ADMIN_PATH` | `/admin` | Admin panel mount path |
| `ADMIN_ENABLED` | `true` | Set to `false` to disable the panel |
| `ADMIN_API_PATH` | `/api` | REST API prefix |
| `ADMIN_AUTH_PATH` | `/auth` | Auth prefix |
| `ADMIN_DB_PATH` | `.data/admin.db` | SQLite database file |
| `ADMIN_BACKUP` | `true` | Set to `false` to disable backups |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | `admin@example.com` / `admin123` | Seed administrator |

## API

| Method | Route | Description |
| --- | --- | --- |
| `GET` / `POST` | `/api/:collection` | List / create |
| `GET` / `PATCH` / `PUT` / `DELETE` | `/api/:collection/:id` | Read / update / delete (`PUT` is a partial update) |
| `GET` | `/api/:collection/relations` | Relation picker options (auth) |
| `POST` | `/auth/login` / `/auth/logout` / `/auth/refresh` | Session management |
| `GET` | `/auth/me` | Current user |
| `GET` / `POST` | `/auth/users` | List / create users (auth) |
| `GET` / `PATCH` / `PUT` / `DELETE` | `/auth/users/:id` | Manage users (auth) |
| `POST` / `DELETE` | `/media` | Media upload and deletion (auth) |
| `GET` | `/files/*` | Served uploads |
| `GET` / `POST` / `PUT` / `DELETE` | `/backup` | Backup management (auth) |

Errors return `{ "message": "...", "errors": { ... } }`.

## Storage and backups

- Database: `.data/admin.db` (SQLite, WAL mode).
- Uploads: `public/files/`.
- Backups: gzip JSON archives in `.data/backups/`, scheduled every 24 hours by
  default (10 kept).

All of these are created automatically and should stay out of version control.

## Localization

Locales are declared in `src/schemas/locales.ts` and in `serenojs.config.ts`.
Localized fields are stored as one column per locale (`title_pt`, `title_en`)
and exposed by the API as nested objects:

```json
{ "title": { "pt": "Comprar pão", "en": "Buy bread" } }
```

The admin UI language (English/Portuguese) is independent from content
localization and can be switched in the sidebar.
